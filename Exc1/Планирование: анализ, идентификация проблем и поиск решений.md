## Проанализируйте схему и описание системы. Идентифицируйте существующие и потенциальные проблемные места. Напишите их список.

### Анализ схемы и описания системы.
1. Можем выделить основные части системы:
- shop
    - web
    - api
    - db
- crm
    - web
    - api
    - db (та же используется и в shop)
- mes
    - web
    - api (непосредственно в самой системе mes cо сценариями логики обработки)
    - db
- 3d files storage (s3)
- event bus (rabbitMq)
2. Все сервисы, располагаются в облаке.
3. Несколько окружений (dev, release, prod).
5. Все сервисы имеют только по одному инстансу.
6. Единая БД у CRM и SHOP.
7. Несколько точек входа для разных типов пользователей
- shop web
- crm web
- mes api
- mes web


### Проблемные места.
1. Жалобы на долгое выполнение заказов (потеря заказов).
2. Большие задержки релизов из за багов (более месяца).
3. Отсутсвие автоматизированных тестов.
4. Отсутвие мониторинга, алертинга, трейсинга.
4. Проблемы производительности (например mes web - загрузка заказов по статусам).
5. Неполный комплект команды (один C# разработчик).
6. Одна БД и на shop и на crm
7. У каждой БД только один инстанс и на запись и на чтение.
8. Возможно отсутствует кеширование (судя по схеме нет key->value хранилища (redis)).
9. Плохо выстроенные процессы (не делается ретроспектива, не делается техдолг, возможно 2-х недельные спринты сейчас не лучший подход).
10. Возможно отсутствует документация.
11. Улучшения ci/cd (автоматическая раскатка релизной ветке на release окружение).
