# Задание 2. Мониторинг

## Добавьте в файл раздел «Мотивация». Напишите здесь, почему в систему нужно добавить мониторинг и что это даст компании.
Для того чтобы сделать систему наблюдаемой, нам требуется внедрение мониторинга как одной из составляющей концепции observability.
Внедрение мониторинга позволит:
- Узнавать о сбоях системы до жалоб пользователей.
- Заранее видеть места системы, которые могут привести к отказу.
- Планирование нужных ресурсов со стороны инфраструктуры на основании изменения показателей.
- Планирование задач для разработки с учетом показателей нагрузок на разные сервисы системы.
- Более быстрый поиск причины возникшей неисправности системы.

1) Мониторинг железа

Имеем, что для всех подсистем следует иметь мониторинг железа по USE подходу.
Подход RED отлично подойдет для мониторинга web систем: в нашем случае это такие подсистемы, 
  как web и api в CRM, Shop, MES 
Также можем применить подход 4 золотых сигнала вцелом к системам как к RabbitMq, так и MES с CRM.


Все метрики Prometheus пр умолчанию будут иметь лейблы instance, job и timestamp.
Для внедрения в текущую систему видится, что этого будет достаточно для успешного построения графиков на разных дашбордах и настройки алертинга.
