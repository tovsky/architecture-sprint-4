# Задание 3. Трейсинг

## Проанализируйте систему компании и C4-диаграмму в контексте планирования трейсинга. 
## Напишите и выделите на схеме системы, которые следует покрыть трейсингом. Для этого идентифицируйте места, где заказ может «сломаться» или зависнуть

Для решения проблемы, что заказы зависают на каком-то сервисе либо в статусе, требуется трасировка всех сервисов,
которые участвуют в логике смены статусов заказа. Тогда сможем установить те сервисы внутри IT ландшафта, где происходит зависание по статусам.

К таким сервисам и взаимодействиям между ними можно выделить:
- Shop API
- CRM API
- MES API
- RabbitMq 

Для трейсинга минимально необходимы данные:
- метки времени
- уникальный correlationId запроса
- уникальный orderId
- serviceName
- instanceId
- дополнительный context (опцианально - может появиться при дополнительном изучении необходимых данных)


## Добавьте в файл раздел «Мотивация». Напишите здесь, почему в систему нужно добавить трейсинг и что это даст компании. 
##   Опишите возможные три-пять технические и бизнес-метрики решения, на которые повлияет внедрение трейсинга.
Внедрение трейсинга даст возможность определить места зависания статусов заказов и исправить эти баги, 
что положительно повлияет на следующие моменты:
1) Выявление и раннее исправление некорректных ситуаций до прямых жалоб пользователей.
2) Уменьшение времени ИТ команды на выявление и фикс багов.
3) Увеличение лояльности пользователей за счет комфортной работы и корректного обещанного функциона системы (те же жалобы на строки от B2C).
4) Возвращение отвалившихся крупных контрактов и недопущение новых (продавцы).
